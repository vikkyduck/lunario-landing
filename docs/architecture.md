# Архитектура — lunario.online

## Хостинг и страна

Действующий Timeweb VDS Виктории (5.129.198.180, Россия) — тот же, где withoutwater,
kotu, vi-utkina. **152-ФЗ: первичная запись заявок — в РФ, выполняется.**
Домен lunario.online куплен на Timeweb → A-запись на VDS.

## Стек (по образцу withoutwater-api — проверен в бою)

- **Фронтенд:** статические HTML + CSS + ванильный JS, шрифты Lora / Golos Text /
  JetBrains Mono хостим сами (не Google CDN — IP пользователей не уходит за рубеж).
- **Бэкенд:** Node ≥22.5 без зависимостей (node:sqlite, node:http), один файл
  `server.mjs`, слушает 127.0.0.1:**5030**, systemd-сервис `lunario-api`.
- **База:** SQLite `/opt/lunario/data/lunario.db` — вне webroot, WAL.
- **nginx:** `/assets/*`, шрифты, картинки — статика напрямую;
  `/`, `/api/*`, `/admin` — прокси на 5030. HTTPS — certbot, security-заголовки.
- **Раскладка на VDS:** `/opt/lunario/{site,backend,data}` + `.env` в `/opt/lunario/`.

## А/Б-тест — как работает

1. Посетитель открывает `lunario.online` → запрос `/` попадает в Node.
2. Если cookie `lunario_ab` нет — сервер выдаёт вариант **строгим чередованием**
   (счётчик в базе: нечётный посетитель → A, чётный → B) и ставит cookie на 90 дней.
   Если cookie есть — отдаёт закреплённый вариант (посетитель всегда видит один и тот же).
3. HTML вариантов собран заранее (два готовых файла, различие — первый экран по ТЗ:
   A «Когда внутри слишком много вопросов…» / B «Личный AI-компаньон…»).
4. Все события с фронта уходят в `POST /api/event` с меткой варианта:
   landing_view, cta_click, form_start, interest_select, lead_sent, form_error,
   faq_open, scroll_50, scroll_90. Персональных данных в событиях нет.
5. Заявка (`POST /api/lead`) тоже несёт вариант → в админке считается воронка
   по A и B: просмотры → клики CTA → начало формы → заявки, конверсия в %.
   Те же события дублируются целями в Яндекс.Метрику (reachGoal).

## Поток заявки

```
форма (чекбокс согласия обязателен)
  → POST /api/lead: honeypot + rate limit (по IP) + валидация контакта
  → SQLite (РФ): поля + вариант + UTM (source/medium/campaign/content/term)
      + IP, время, версия текста согласия, отметка рекламного согласия
  → Telegram владелице: «Новая заявка №N · вариант A» — БЕЗ персональных данных
      (токен бота вводит Виктория; поддержан TELEGRAM_API_BASE-прокси, как в withoutwater)
  → ответ фронту: «Вы в списке!» (повторный контакт: «Мы сохранили ваше место»)
  → админка /admin (basic auth): таблица, статусы новая/в работе/закрыта,
      CSV, удаление записи (для запросов на удаление), статистика А/Б
```

## Данные: что, зачем, сколько храним

| Поле | Зачем | Срок |
|---|---|---|
| Имя (необязательное) | Обращение при приглашении | До приглашения в приложение, max 2 года, либо до отзыва |
| Telegram или email | Сообщить о запуске | тот же |
| Интересы (чипы) | Приоритизация функций | тот же |
| UTM, вариант А/Б | Оценка каналов и теста | тот же |
| IP, время, версия согласия | Доказательство согласия (ст. 9 152-ФЗ) | вместе с заявкой |
| События аналитики | Конверсия А/Б | Без ПД, обезличены — не ограничен |

Отзыв согласия: письмо на vu@withoutwater.ru или @eratochka → удаление из админки.
Бэкап SQLite: cron ежесуточно, 30 копий, на этом же VDS (РФ).

## Роли

- Оператор ПД: Уткина Виктория (физлицо). Доступ к данным — только она (админка + SSH).
- Обработчики-третьи лица: нет (хостинг Timeweb — РФ; Метрика — обезличенные счётчики, РФ).
- Трансграничной передачи нет (в Telegram ПД не отправляются).
